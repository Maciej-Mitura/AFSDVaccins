# Phase 36E — Stop-scoped courier voice reports

## Summary

Voice reports move from a single route-level control to **per-stop** delivery
reports. New uploads require `stopId`. Legacy route-level documents (no
`stopId`) remain readable and are never auto-associated with a stop.

## Compatibility model

| Field                | New uploads                             | Legacy rows |
| -------------------- | --------------------------------------- | ----------- |
| `routeId`            | required                                | required    |
| `stopId`             | required                                | null/absent |
| `apothekerProfileId` | denormalised from stop (server-derived) | null        |
| `clientUploadId`     | required (unchanged idempotency)        | present     |

- Do **not** replace `routeId` with `stopId`.
- Do **not** destructively migrate legacy rows.
- No guessed stop association for legacy reports.
- No migration step runs at API startup for voice reports.

## Lifecycle / ownership policy

Recording allowed when:

1. Route status is `IN_PROGRESS`
2. Stop exists on that route
3. Authenticated courier owns the assigned route
4. Before or after arrival; after QR confirmation still allowed while IN_PROGRESS

Recording rejected when route is `COMPLETED` or `CANCELLED`.

Multiple reports per stop are allowed. Retries use `clientUploadId` (no silent replace).

**APOTHEKER:** still denied for list/upload/stream (unchanged). Pharmacist
visibility could be appropriate later for delivery confirmation context, but is
**not** enabled in 36E.

## Final generated GraphQL contract

Canonical generation (do not invent a second workflow):

```bash
npm run generate:graphql
# = generate:schema (@vaccin-delivery/api nest build + schema dump)
# + generate:types (@vaccin-delivery/types graphql-codegen)
```

PWA operation types are produced in the same `@vaccin-delivery/types` pass
(`documents: packages/pwa/src/assets/graphql/**/*.ts`). Artefacts land in
gitignored `packages/api/dist/schema.gql` and `packages/types/dist/graphql.ts`
and are regenerated by `typecheck:pwa` / `build:pwa*`.

Verified public fields on `RouteVoiceReport`:

| Field                 | Nullability        |
| --------------------- | ------------------ |
| `stopId`              | nullable `ID`      |
| `stopSequence`        | nullable `Int`     |
| `pharmacyDisplayName` | nullable `String`  |
| `isLegacyRouteReport` | non-null `Boolean` |

`RouteVoiceReportUpdate` (subscription payload) includes nullable `stopId`.

Explicitly **absent** from GraphQL / REST client responses: `blobName`,
container name, SAS/private storage URLs, full `sha256`, `apothekerProfileId`,
recorded-by user IDs.

REST multipart upload client contract (`RouteVoiceReportUploadPayload`):
`stopId: string` is required; FormData always appends `stopId`.

## API-first deployment compatibility

| Surface                          | Old PWA after new API deploy                    |
| -------------------------------- | ----------------------------------------------- |
| GraphQL report queries           | Continue working (additive nullable fields)     |
| GraphQL subscriptions w/o stopId | Continue working (stopId optional in selection) |
| Route-level report **reads**     | Continue working (legacy + new rows)            |
| Route-level REST **upload**      | **Rejected** — see below                        |

### Temporary old-PWA upload limitation

After API deploy and **before** PWA deploy, an old courier client that POSTs
multipart **without** `stopId` receives HTTP **400** with:

- `error`: `ROUTE_VOICE_REPORT_STOP_ID_REQUIRED`
- clear message that stop-id is required; route-only uploads are not accepted

No route-level report document is created. No silent fallback.

**Rollout window risk:** medium for courier **create** only; low for reads,
playback, ADMIN list, subscriptions, QR, arrival, and route completion. Prefer
deploying API then PWA in the same maintenance window (minutes, not hours) so
couriers are not left unable to upload mid-route.

Mitigation: consecutive API → PWA deploy; communicate brief upload outage for
old clients; do **not** re-enable route-only creates for compatibility.

## Azure blob organisation

**New path:**

```text
route-voice-reports/{routeId}/stops/{stopId}/{reportId}/audio.{ext}
```

**Legacy path (still readable / cleanup-valid):**

```text
route-voice-reports/{routeId}/{reportId}/audio.{ext}
```

Metadata on new blobs (safe IDs only): `reportid`, `routeid`, `stopid`,
`sha256prefix`. Values are sanitized to Azure naming constraints (ASCII keys /
bounded lengths). No pharmacy/person names in path or metadata.

No blob migration. Cleanup / validation accepts both path shapes. Local
automated tests use the fake storage provider; real Azure is production-only.

## Transcription

Unchanged Azure Speech flow. Lease/retry remains idempotent. `stopId` is
persisted on the report document and included in redacted PubSub + structured
logs (`reportId`, `routeId`, `stopId`). Never log audio, SAS, tokens, or
transcript content beyond existing policy.

## Courier UI

- Global route-tools recorder removed from the normal workflow.
- Each stop mounts a stop-bound recorder near QR / arrival actions.
- Global microphone mutex: one active recording at a time.
  - Opening Stop B while Stop A holds the mic cancels A after confirm (or keeps A
    if the user declines).
  - Unmount / navigation / logout releases mutex + media tracks.
  - Route leaving `IN_PROGRESS` cancels active recording and releases mutex.
  - Failed upload returns to preview; microphone tracks are already stopped at
    preview time (no second MediaRecorder).
- Legacy reports appear in a separate “Legacy route reports” section.

## ADMIN UI

- Route planning voice list groups by stop + legacy section.
- Stop/pharmacy context on cards; no raw IDs as primary labels.
- Playback/retry via existing authorised mechanisms (no eager blob load).

## Indexes

- Existing: `(routeId, createdAt)`, courier idempotency, transcription lease
- Added: `(routeId, stopId, createdAt)`, `(apothekerProfileId, createdAt)`

## Exact deploy sequence

1. Deploy **API** (additive GraphQL + required `stopId` on REST upload).
2. Verify health / schema introspection; confirm old PWA upload returns
   `ROUTE_VOICE_REPORT_STOP_ID_REQUIRED` (no row created).
3. Deploy **PWA** (per-stop recorder + FormData `stopId`).
4. Verify stop-level upload + ADMIN grouping on a live IN_PROGRESS route.
5. Retain legacy read/playback/cleanup indefinitely.

## Rollback sequence

1. Roll back **PWA** first if the new UI is defective (old PWA will hit
   `STOP_ID_REQUIRED` until API is also rolled back — upload remains blocked).
2. Roll back **API** to restore route-level upload acceptance if couriers must
   record again before a forward fix.
3. Prefer forward-fix of PWA over dual rollback when only the client is wrong.
4. Never delete or rewrite legacy Mongo rows as part of rollback.

## Legacy data behaviour

Persisted pre-36E rows (`routeId` set, `stopId` absent/null, legacy blob path):

- API list/GraphQL: `stopId` null, `isLegacyRouteReport` true, no pharmacy/stop guess
- ADMIN: rendered only under the legacy section
- Authorised playback streams via the stored legacy blob name
- Stale-upload cleanup deletes the legacy path when applicable
- No startup migration

## Manual / real-device checks (remain necessary)

1. Physical microphone + mobile Safari/Chrome MediaRecorder codecs
2. Concurrent QR camera + voice mic handoff on device
3. ADMIN retry after a real Azure Speech failure
4. Real Azure Blob: stop-scoped path + metadata keys only; authorised Range
   playback for both new and legacy blobs
5. End-to-end: Stop A upload appears only under Stop A; Stop B empty of A’s
   report; route completion blocks new recording; existing reports remain
   playable
6. Microphone cleanup: leave route, logout, and failed upload leave no active
   `MediaStream` tracks in browser DevTools
